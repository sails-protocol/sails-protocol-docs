The Sails Protocol node exposes a versioned REST API under `/v1/*`, plus WebSocket channels for real-time trade communication. Every request and response body is JSON. Application-facing flows are organized around the Intent lifecycle: you express what you want to do, and the node coordinates the underlying modules.

## Base URL

Point your client at the URL of your Sails node. For local development, the reference implementation runs at:

```text
http://localhost:3000
```

<Note>
  Sails Protocol is self-hosted — there is no shared cloud endpoint. In production, use the URL of the node you run or integrate with.
</Note>

## API modules

Routes follow the convention `/v1/{module}/{resource}`:

| Module | Prefix | What it covers |
| --- | --- | --- |
| OpenIdentity | `/v1/identity` | Participant registration, challenge-response authentication, WebSocket tickets |
| OpenLiquidity | `/v1/liquidity` | Publish, discover, and match offers; order book |
| OpenP2P | `/v1/openp2p` | Trades, trade status, message history, real-time chat |
| OpenSettlement | `/v1/settlement` | Escrow lifecycle, signature collection, disputes, arbitration, payout addresses, payment accounts |
| OpenReputation | `/v1/reputation` | Trust scores, leaderboard, ratings, vouches |
| OpenProof | `/v1/proof` | Claims, proofs, verification, evidence, trade evidence bundles |
| OpenAgents | `/v1/agents` | On-device AI: intent generation and risk assessment |
| Capabilities | `/v1/capabilities` | Capability grants |
| Peers | `/v1/peers` | P2P transport node (HyperDHT) |

The Intent Engine lives at `/v1/intents`, outside the module convention: Intent is a cross-cutting protocol primitive, not owned by any single module.

## Health and operations

| Endpoint | Purpose |
| --- | --- |
| `GET /health` | Basic liveness plus node metadata and feature flags |
| `GET /health/live` | Liveness probe — the process is up |
| `GET /health/ready` | Readiness probe — checks PostgreSQL and Redis; returns `503` with `status: "not_ready"` if either fails |
| `GET /metrics` | Prometheus metrics |
| `GET /` | Node overview (name, protocol, version, WebSocket path) |

A healthy node responds to `GET /health` with:

```json
{
  "status": "ok",
  "timestamp": "2026-09-21T10:00:00.000Z",
  "version": "0.2.0",
  "protocol": "Sails Protocol",
  "module": "Sails OpenP2P",
  "referenceImplementation": "Satsails Wallet",
  "features": {
    "mockEscrow": false,
    "mockSettlement": false
  }
}
```

`GET /health/ready` reports each dependency with its latency:

```json
{
  "status": "ready",
  "timestamp": "2026-09-21T10:00:00.000Z",
  "checks": {
    "postgres": { "ok": true, "latencyMs": 2 },
    "redis": { "ok": true, "latencyMs": 1 }
  }
}
```

## Response format

Successful responses wrap the result in a `data` envelope with a `success` flag:

```json
{ "success": true, "data": { "...": "..." } }
```

The HTTP status code carries the outcome (`200` OK, `201` Created). Error responses always have this shape:

```json
{
  "success": false,
  "error": "NOT_FOUND",
  "message": "Participant not found: 5b1c…",
  "details": [],
  "requestId": "req-7f3a1c",
  "docsUrl": "https://github.com/sails-protocol/Sails-Protocol/blob/main/docs/API_REFERENCE.md#9-error-response-shape"
}
```

Every error includes a `requestId` that matches the node's log line for that request — include it when you report an issue.

| `error` | HTTP status | Meaning |
| --- | --- | --- |
| `VALIDATION_ERROR` | 400 | Request body or query failed validation. `details` lists the failing fields. |
| `AUTH_ERROR` | 401 | Missing or invalid session token, or a signature that did not verify |
| `FORBIDDEN` | 403 | Authenticated, but not authorized for this resource or action |
| `NOT_FOUND` | 404 | The referenced resource does not exist |
| `ESCROW_ERROR` | 409 | An escrow or settlement action was attempted from an invalid state |
| `RATE_LIMIT_EXCEEDED` | 429 | Too many requests — retry after the time indicated in the response headers |
| `REQUEST_ERROR` | 4xx | Request rejected for a reason not covered above |
| `INTERNAL_ERROR` | 500 | Unexpected server error. The message is redacted outside development mode. |

## Authentication

Most endpoints require a session. Pass your session token in the `Authorization` header:

```text
Authorization: Bearer <your-session-token>
```

Sails uses Ed25519 challenge-response authentication — no passwords or API keys. Your participant ID is always derived from the session, never from the request body. See [Authentication](/api/authentication) for the full flow.

WebSocket connections can't carry an `Authorization` header, so they authenticate with a short-lived, single-use ticket from `POST /v1/identity/ws-ticket`. See [WebSocket](/api/websocket).

## Amounts

All financial amounts are **decimal strings** (for example `"0.0015"`), never JSON numbers. This keeps exact precision across languages and runtimes.

## Versioning

All routes are prefixed with `/v1/`. The public TypeScript SDK (`@satsails/p2p-trading-sdk`, currently `0.2.0`) follows a pre-v1 compatibility contract: documented methods don't change incompatibly before v1 — only additive changes are made. When a future major API version ships, its routes will be introduced alongside `/v1/` before the older version is retired.

<Tip>
  In non-production environments, the node serves an interactive OpenAPI (Swagger) UI at `/docs` for exploring and testing endpoints. It's disabled in production.
</Tip>
